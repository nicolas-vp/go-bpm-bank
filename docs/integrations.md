# Учебная мок-АБС и надёжность

> Только учебные цели. Авторы не несут ответственности за решения на основе примера и последствия использования. Это собственный REST-контракт, не API RS-Bank.

`cmd/mock-core-banking` — отдельный HTTP-сервис и отдельная PostgreSQL-база bank_core. Банк обращается к нему через `internal/bpmgen/services`; прямого доступа к его таблицам у процессов нет. Для компактности сервис также содержит логически отдельные моки проверок, договора, архива, сообщения ФНС и уведомления.

## Контракт

| Метод | Назначение |
|---|---|
| POST /v1/checks/document | VALID / INCOMPLETE; синтетическое свидетельство проверки |
| POST /v1/checks/screening | CLEAR / MATCH / PEP |
| POST /v1/checks/tax | VALID / REVIEW |
| POST /v1/customers/resolve | Идемпотентная учебная карточка клиента |
| POST /v1/account-openings | Команда открытия; applicationId, customerId, contractId, scenario |
| GET /v1/account-openings?requestId=... | Сверить результат потерянного ответа |
| GET /v1/account-openings/{operationId} | Состояние операции и регистрационная запись |
| POST /v1/effects/contract | Учебный договор |
| POST /v1/effects/archive | Досье |
| POST /v1/effects/tax-report | Учебное сообщение ФНС |
| POST /v1/effects/notification | Учебное уведомление |
| GET /v1/state | Диагностический список операций и счётчиков попыток |
| GET /healthz | Доступность сервиса и его БД |

Реквизит DEMO-... намеренно не является действительным банковским номером. Источник сведений проверок — synthetic-v1, не реальные государственные реестры. applicationId и фиксированная версия команды образуют устойчивый ключ, который не меняется при повторе задачи.

## Идемпотентность

Заявление: уникальная строка bank_applications и StartProcessTx в одной транзакции. Тот же applicationId с тем же сценарием возвращает существующий instanceId, изменённая команда — 409. При откате транзакции не остаётся ни заявления без процесса, ни процесса без заявления.

Открытие: ключ `applicationId:opening:v1`. В mock_openings уникальны request_id, operation_id и account_id. Сохраняется хеш канонизированной команды. Повтор с тем же телом возвращает операцию; изменённое тело — 409. При повторе обработчик сначала сверяет запись GET-запросом. Только 404 означает, что нужно послать команду; недоступность сервиса не считается отсутствием операции.

В сценарии lost_response запись коммитится, а первый ответ намеренно теряется (503). Следующая попытка сверяет БД мок-АБС и не открывает второй счёт. PostgreSQL-хранилище позволяет пересоздать серверный объект/перезапустить процесс без потери ключа.

Досье, налоговое сообщение и уведомление имеют отдельные устойчивые ключи и счётчики попыток. CONFIRMED подтверждает только наш учебный эффект.

## Таймеры и ошибки

- Проверки после исправления анкеты выполняются снова. Все параллельные ветки доходят до join; каждую область результатов возвращает только её владелец.
- Вызов внешнего HTTP ограничен пятью секундами; service task допускает шесть попыток.
- При PENDING открытие опрашивается через BPMN-таймер PT1S. В мок-сценарии core_pending оно завершается после повторного опроса. Произвольное бесконечное ожидание реальной АБС и контроль юридического срока требуют дополнительной эскалации; в этом демо она не реализована.
- Таймеры PT5M анкеты и PT2M рассмотрения — внутренние учебные SLA.
- REJECTED от мок-АБС приводит к REFERRED_CORE. Это не трактуется как законный отказ физлицу.
- После OPENED нет автоматического закрытия при ошибке архива, ФНС или уведомления. При исчерпании повторов подпроцесс технически упадёт, а счёт в мок-АБС останется открытым. Результат операции и статус постобработки различаются.
- В этом варианте нет callback/webhook: используется устойчивая сверка статуса. Поэтому не заявляется обработка сообщений от реальной АБС.

Чего не обеспечивает демо: промышленная аутентификация, защищённые внешние каналы, реальная подпись, неизменяемый юридический аудит, полный ПВК, банковский календарь, боевые регистры/проводки и формат отчётности. Число сценариев не означает нормативной полноты.

Механика очереди, повторов и эксплуатации: [go-bpm](https://go-bpm.tech/docs/running/). Как service task превращается в Go-обработчик: [генератор](https://go-bpm.tech/docs/generator/).
